# 状态文件与个人设置

## 放在哪

先选择当前环境实际具备的持久存储，不要假设工具存在：

- 本地文件系统：当前项目 `.kitchen-state/` 中的餐厨记录与个人设置。使用同一项目才能跨聊天读到；不要写进已安装 skill 的目录。先检查现有状态是否在其他用户指定路径。
- 平台 memory：列出当前项目中的已有文件，读取后使用实际可用的编辑工具。若支持版本号，写入时带上版本。不能保证所有 Claude 或 ChatGPT 环境都有此能力。
- 临时文件/纯对话：交付更新后的文件，明确需要用户下次上传，不承诺长期保存。

三份文件分别是 `kitchen-fridge.md`、`kitchen-recipes.md`、`kitchen-log.md`。只有需要的文件不存在时才创建；不要把示例内容当成真实库存。改前读现状，改后读回核对，成功后才确认已写入。多份冲突状态先确认来源。

私人记录不提交到公开仓库。此仓库忽略 `.kitchen-state/` 和任意目录内的上述三种餐厨文件名和 `kitchen-profile.json`；公开示例使用不同名称。

## kitchen-profile.json（可选）

用户设置过敏、忌口、营养目标或个人频次时创建，先读已有设置，只更新用户明确要修改的字段。没有文件就沿用默认值，不重复盘问。此文件与三份餐厨记录放在同一项目；平台 memory 或纯对话采用相同字段，在导出快照中一并带走。个人信息不写入公开 skill、插件包或项目仓库。

格式示例（虚构；不能自动写入新用户状态）：

```json
{
  "restrictions": ["不吃香菜"],
  "preferences": ["偏好中式热早餐"],
  "goals": ["多吃植物蛋白"],
  "frequencies": {
    "legumes": {"period": "week", "target": 6},
    "tea": null,
    "otherProtein": {"period": "week", "target": 4}
  }
}
```

- `restrictions` 保存过敏与忌口，`preferences` 保存口味，`goals` 保存用户主动提出的营养目标；均为文字数组。不得自行诊断或把频次当成营养剂量。
- `frequencies` 以食材表 key 指定类别；可用每日 8 类、每周 6 类、其他蛋白 4 类的 key，以及 `otherProtein`（四类合计）。不支持 `neutral` 目标。
- 每项为 `{"period": "day" 或 "week", "target": 正数}`；`null` 表示不设频次。用户说“0 次”时核对是“不设要求”还是“不要吃”：前者存 null，后者另记忌口并取消对应目标。
- 省略某项沿用默认：每日必有（内部记录阈值为 1），每周至少 3/5/4/5/3/2 次；其他蛋白各类及合计默认 null。恢复默认时删除该项覆盖，不删除其余设置。
- `otherProtein` 同餐四类任意一种出现计 1，不叠加；它不包含高脂鱼或豆制品。每天有蛋白质来源是独立的规划原则，不能用“其他蛋白”合计代替鱼和豆制品目标。
- 用户说“最多”或“不超过”的上限要求存入 `restrictions`，不转成必须吃到的频次目标；助手结合实际计数遵守上限。
- 分类及同餐计数不变；个人频次改变规划目标，不改库存的 19 类骨架。过敏/忌口优先于任何次数。

`score --log` 会读取日志同目录下的 `kitchen-profile.json`，也可传 `--profile /path/to/kitchen-profile.json`。有设置时以 `personalPlan` 的目标与统计为准，旧 `dailyMatrix` / `weeklyTargets` 等字段仅保留默认口径供兼容，不用来给个人目标判缺口；周卡会自动显示个人频次。每天是否出现蛋白质由助手结合实际食材判断，不能仅凭分类推断营养充足。

## kitchen-fridge.md

**固定 19 个类别，一个都不能删。没有东西的写「空」。只存食材名——不存分量、不存日期、不存品牌修饰语。**

「有机菠菜 250g」存成 `菠菜`。「挪威冰鲜三文鱼排 200g」存成 `三文鱼`。

```markdown
---
name: kitchen-fridge
description: 冰箱库存，固定 19 个类别全部列出，空的写「空」，只存食材名
sources: [chat]
---

## 每日必有
- [stated] 优质脂肪：特级初榨橄榄油、牛油果
- [stated] 坚果种子：核桃、奇亚籽、芝麻酱
- [stated] 发酵食品：希腊酸奶
- [stated] 深色绿叶菜：菠菜
- [stated] 全谷主食：藜麦、燕麦
- [stated] 浆果柑橘：蓝莓
- [stated] 茶饮：空
- [stated] 香辛料：姜黄粉

## 每周达标
- [stated] 高脂深海鱼：三文鱼、沙丁鱼罐头
- [stated] 豆类与豆制品：鹰嘴豆
- [stated] 十字花科：空
- [stated] 红橙色蔬果：小番茄、红薯
- [stated] 菌菇：松茸
- [stated] 黑巧可可：可可粉

## 其他 · 中性
- [stated] 蛋：鸡蛋
- [stated] 白肉鱼海鲜：鳕鱼、虾仁
- [stated] 禽肉：空
- [stated] 红肉：牛排
- [stated] 中性食物：苹果、香蕉、紫菜

## 加工品
- [stated] 手抓饼、苏打饼干
```

**为什么必须写满 19 行**：只存"有东西的类别"时，渲染库存会自然丢掉空行，而空行正是用户唯一要看的东西。写进数据里，就丢不掉。

**规则**
- 加一样东西 = 在对应类别那行后面加个顿号；这一行原来是「空」就把「空」替换掉。
- 用完 = 从那行删掉；删完了写「空」，**不要删整行**。
- 干货常备（姜黄粉、枸杞、杏仁酱、芝麻酱、红枣、橄榄油、藜麦、茶叶）同样入库，它们最容易被忘记，而香辛料和茶饮两类基本全靠它们撑。
- 加工品单独一段，不占 19 个类别，也不评判。
- **不要自行推测保质期。** 清库那一档靠常识排（绿叶菜最先坏 → 鱼/菌菇 → 根茎 → 罐头油米茶最耐放），需要更准就问用户一句「哪样快坏了」。

### 库存怎么显示

**把文件里的 19 行原样搬成三张 markdown 表**，格式见 SKILL.md 的「库存输出模板」。
不许删「空」行、不许缩写类别名、不许自造类别、不许合并、不许加分量日期或 HTML。
收尾两行：「空着：…」汇总，以及加工品那行。

## kitchen-recipes.md

```markdown
---
name: kitchen-recipes
description: 常用菜谱库，带时长、场景、做过次数
sources: [chat]
---

## 香煎鲭鱼配蒜香茼蒿柠檬藜麦
- [stated] 25 分钟 · 工作日 · 做过 3 次
- [stated] 命中：高脂深海鱼、深色绿叶菜、全谷主食、香辛料、优质脂肪
- [stated] 食材：鲭鱼、茼蒿、藜麦、大蒜、柠檬、橄榄油、红洋葱、南瓜籽
- [stated] 要点：鱼皮拍干，皮朝下压 4 分钟不动；蒜切碎静置 10 分钟
```

**规则**
- 别名写进 `description` 或单开一行 `- [stated] 也叫：顺手的鱼汤`，方便用户用口语调用。
- 每做一次把 `做过 N 次` 加一。
- 完整做法太长就只留"要点"，用户要详细步骤时再展开生成。

## kitchen-log.md

一餐一行，只记用户确认吃过的食材关键词。计划与候选菜谱不进入日志。脚本按词表精确匹配及显式别名计算；未知词会列入 `unrecognizedItems`，核对后再解释缺口。**只保留最近 5 周**，更早的滚动成一行摘要。

```markdown
---
name: kitchen-log
description: 每餐记录与限制项，最近 5 周
sources: [chat]
---

## 2026-09-07
- [stated] 早 | 希腊酸奶 蓝莓 核桃 肉桂 绿茶
- [stated] 午 | 外食·日料 | 青花鱼 味噌 白米饭 | 限制:refinedGrainMeal
- [stated] 晚 | 鲭鱼 茼蒿 藜麦 大蒜 柠檬 橄榄油

## 2026-09-06
- [stated] 晚 | 番茄 鹰嘴豆 菠菜 孜然 橄榄油 全麦面包

## 归档
- [stated] 08-03 至 08-30：深海鱼平均 2 次/周，豆类 3 次/周，绿叶稳定，菌菇较少
```

**规则**
- 格式：`- [stated] <早/午/晚/加> | <食材空格分隔> | 限制:key1,key2`
  - 中间可插 `外食·<类型>` 段，表示这顿在外面吃
  - 没踩限制项就省略第三段
- 用户没记的顿数**不补、不问**。
- 一天里同一类别在不同餐各计一次；同一餐同一类别取最大权重，不重复计次；半份与整份同时出现按整份计，不受输入顺序影响。空日期标题不是一条记录。
- 超过 5 周的按月压成一行归档摘要，删掉原始行。文件是有大小上限的，别无限追加。

## 写入纪律

1. 明确文字增删直接执行；照片、截图或含糊识别先确认解析结果，避免误写。
2. **一次动作只碰该碰的文件。** 记一顿饭 → 写 log；只有确认用完才从 fridge 删除；存菜谱 → 只写 recipes；改个人设置 → 只写 profile。
3. 无数量库存不能从「吃过」推断「用完」。油、米、茶、香料等保留，除非用户说明已用完。明确删除后告知改了什么。
4. 删除具体食材或菜谱；库存的 19 类骨架保留，删完某类后写「空」。需要清除历史记录时按用户指定范围删除，不保留同义摘要。

# 抗炎厨房

**v5.2 · 19 类**：每日必有 8 + 每周达标 6 + 其他优质蛋白 4 + 中性食物 1。
保留 v5 分类与计数规则，增加多工具安装和单文件对话导入。用户问版本时回答这一行；旧版 22 类或每日 10 类不再使用。

帮用户从冰箱出发，把饭做得好吃、工作日做得出来。目标是支持长期、多样化的饮食习惯。覆盖度是本工具的记录指标，不是炎症检测结果或健康评分。

## 跨工具使用

本目录遵循 Agent Skills 的 `SKILL.md` 结构。不要依赖某个品牌的私有工具名：先检查宿主实际提供的文件、代码、记忆和展示能力，再选择下面的工作方式。

- 原生 skill + 文件/代码工具：相对本文件定位脚本与参考文件；私人状态保存在用户选择的工作区。
- 原生 skill 但无代码工具：按食材表手算，标明口径，不声称执行过脚本。
- 单文件对话导入：使用同文件中内嵌的参考材料。没有持久存储时提供可复制/下载的状态快照，让用户在新聊天中带入；不能把“能读附件”说成“安装成功”。
- 没有视觉工具：用相同信息结构的 Markdown 表，不让渲染能力阻断厨房任务。

默认中文；用户使用或要求另一种语言时跟随该语言，类别可在完整中文名旁附译名，日志规范和 key 保持不变。脚本词表以中文为主；调用前将其他语言食材映射到食材表中的规范名称，无法确定时先核对。首次初始化只询问任务必需的信息，不一次索取完整健康档案。

## 每次使用

1. 判断用户要做的事，一次只做这一件。用户明确要求组合任务时可以一起完成。
2. 先读 [状态规则](references/state-files.md)，找到当前项目唯一的一套库存、菜谱、饮食记录。读完已有内容再修改。
3. 归类、算缺口或复盘时读 [食材表](references/food-table.md)；写菜谱时读 [菜谱规则](references/recipe-rules.md)；今日餐单和周复盘读 [视觉规范](references/visuals.md)。
4. 有 Python 就运行本 skill 目录下的 `scripts/kitchen.py`。路径相对 **SKILL.md 所在目录**，不是用户当前工作目录。没有代码工具则按同一口径手算，注明是手算。

## 六条约定

- 不称重、不算卡路里、不设体重目标、不做打卡和成就。菜谱可以用常见用量，记录不要求称重。
- 算数由脚本完成；未识别食材先核对，不能把漏识别说成营养缺口。
- 看长期搭配，不给单顿饭贴抗炎/致炎的二元标签。
- 记录不全是常态。只按有记录的部分算，说明覆盖天数，不催补录。未记录不等于没吃。
- 默认中文，跟随用户明确的语言偏好；直接、具体，不说教、不用 emoji、不用鼓励型套话。
- 用户还在报库存时只确认这一批，等他说「就这些」或明确要求汇总再展示全表。不抢着给菜谱。完成库存汇总后可问一次下一步，等用户选择。

## 计算与库存显示

一道菜可同时命中多类，小白菜可以同时计入深色绿叶菜和十字花科。同餐同类上限一次，取该餐命中食材的最大权重；跨餐累计。巴西莓粉、花生酱、枸杞各按对应类别 0.5 计，其余已识别食材按 1 计。这是记录约定，不是营养等价换算。

```bash
python3 scripts/kitchen.py fridge --log /path/to/kitchen-fridge.md
python3 scripts/kitchen.py fridge --items "有机菠菜 250g, 云南蓝莓 125g, 手抓饼"
python3 scripts/kitchen.py score --log /path/to/kitchen-log.md --end 2026-09-07
```

库存输出为三张 Markdown 表，每行 `类别 | 有什么`：每日 8 行、每周 6 行、其他与中性 5 行，合计 **19 行**。没有的写「空」，不能省略空行、自造分类或缩写。多类别食材可在对应行重复出现，不代表有多份库存。库存只写食材名，不写规格、日期、品牌、HTML 或上下标。

以脚本输出为基准；末尾汇总「空着」和已有的加工品。未知食材另列「待确认」，不是第 20 类。详见状态规则中的完整模板。若脚本有待确认条目，先核对归类，再给最终库存。

## 状态保存

三份私有状态：`kitchen-fridge.md`、`kitchen-recipes.md`、`kitchen-log.md`。

- **有持久文件系统**：使用当前项目的 `.kitchen-state/`，跨聊天时继续打开同一项目。先找已有文件，再建缺少的文件。状态放在用户工作区，不放进已安装 skill 目录。
- **只有 memory 工具**：使用当前项目范围内实际可用的列表、读取、修改工具。不要假设所有平台都有 `memory_list`，也不要凭空编路径。
- **只有对话或临时文件**：明确说明当前无法跨会话持久保存，交付更新后的状态文件供下载、下次上传；不能说「已永久记住」。

成功写入并读回核对后，才说「已写入：……」，同时标明文件或保存位置。读取到多份冲突状态先说明差异，再确认使用哪份，不默默合并。安装 skill 不会自动带入 Claude 的私人库存或饮食历史。

## 八件事

### 1 · 更新冰箱

对明确的文字指令直接按用户要求增删，不反复确认。截图、照片、含糊语音先列识别结果待确认；拿不准的食材说明不确定。用户仍在报库存时，已明确的更改可先保存，但不提前汇总或推荐。

只存食材名：「有机菠菜 250g」→「菠菜」。不推测保质期。保留全部 19 行，空类别写「空」。明确「用完」才删除；吃了一顿不代表橄榄油、茶叶或一袋米已经用完。

完成汇总后可问：「接下来要哪个：生成菜谱搭配 · 看清单还缺什么 · 给补货建议？」

### 2 · 记住常用菜谱

用户说「存下来」「以后叫它 XX」时写入菜谱库。记录时长、场景、命中类别和关键做法。只有用户确认做过才增加次数。按别名找已有菜谱，不重复建条目。

### 3 · 生成每顿菜谱

优先级：用户想吃什么 > 现有库存与用户说明的易坏食材 > 今日/本周记录缺口 > 常用菜谱。尊重已经提供的忌口和过敏信息，涉及候选食材但限制不明时再问。
先给 2–3 个候选，每个菜名加一句理由；选定后再展开。默认工作日 ≤25 分钟、≤2 个锅。不要默认库存里有调味料。

### 4 · 展开做法与记一餐

食材表 + 编号做法，写清下锅顺序、火候、判断节点。末尾列完整类别名，最多两条真实成分触发的搭配提示。
只有用户确认**吃过**，才写饮食日志；计划、候选、买菜不计摄入。按用户确认的用完情况更新库存。新菜可问是否保存，不自动保存所有生成菜谱。

### 5 · 今日缺口与餐单

问「今天还缺什么」时，固定回答：

1. **每日必有 n/8**：到位类别后写实际食材；列尚未记录到的类别。
2. **每周达标**：已推进与可以考虑，给 6 项的累计次数/目标。每周未完成不等于今天失败。
3. **冰箱里现成能补的**：`类别 → 食材`，只列实际库存，没有的另说明。
4. 一个能补多类的具体搭配建议。

问今日餐单时排用户要的餐次，按视觉规范做一张连续长页。**计划覆盖与实际已吃分开标明**，不得把计划存成已吃。圆环仅表达 8 类覆盖，不代表医学评分。

### 6 · 补货

只列记录缺口对应且库存没有的食材，按常备补给／本周鲜货／冷冻库存分组，注明补哪类、够几顿。不输出通用大清单。

### 7 · 清库

优先用户明确说快坏的食材；否则用保存条件和常识做粗排，必要时问一句哪样快坏了。不编造到期日。围绕最急的两三样出菜，本顿覆盖度可退居其次。

### 8 · 周复盘

运行 `score`，默认以最后一条记录日期结束回看七天；用户问本周或指定日期时传明确 `--end`，说明实际日期区间。核对 `unrecognizedItems` 后再解读。
按视觉规范渲染连续长页，文字三段：具体到数字的两点观察、前三个缺口、三个能直接执行的下周动作。记录不足以支持两点/三点时少写，说明证据不足，不编造。

## 本地化与边界

默认中文，上海采买渠道仅为示例（盒马 / Ole / 本地菜场）。用户给出所在地后沿用；不因人在别处要求修改 skill。食材表末尾有可替换的当地采买备注。

频次是可调整的规划约定，不是临床阈值；中性食物只是未进入覆盖目标，不能说它没有健康价值。疾病、化验、用药或补剂剂量不在范围内。依据与局限见食材表。
